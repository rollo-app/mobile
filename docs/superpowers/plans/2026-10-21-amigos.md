# Amigos y sumar amigos a un rollo — plan de implementación

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** amistad por link de 1 hora, lista de amigos, y que cualquier miembro de un rollo sume a sus amigos (salirse y que el admin saque).

**Architecture:** el backend (Hono + D1) suma tablas de amistades, links y reclamos, endpoints nuevos y la marca `left_at`; la app suma el dominio `friends` en `src/features/`, rutas finas en `app/` y el manejo del link `rollo://friends/<CODE>`. Primero el backend (una PR, tareas B1–B4 en orden), después la app (una PR, tareas A1–A4) sobre el contrato ya generado.

**Tech Stack:** Cloudflare Workers + D1 + zod-openapi + vitest (backend); Expo SDK 58, Expo Router, TanStack Query, jest-expo (app).

**Spec:** `docs/superpowers/specs/2026-10-21-amigos-design.md` (repo de la app). Cada worker lee el spec y el CLAUDE.md de su repo.

## Global Constraints

- Link de amistad: vale **1 hora** desde que se genera; **multiuso** mientras viva; al generar uno nuevo, el anterior deja de servir.
- Código = **8 caracteres** del alfabeto `ABCDEFGHJKMNPQRSTUVWXYZ23456789`; se guarda **hasheado** (SHA-256). El link es `rollo://friends/<CODE>`.
- El vencimiento se chequea **en el server al abrir** (`claim`); el permiso de canje (`claimToken`) dura **24 horas**.
- La amistad es **simétrica** y se crea **sin aceptación**; nadie es amigo de sí mismo; repetir no da error.
- Sumar amigos: **cualquier miembro** suma a **sus** amigos, directo; respuesta **por amigo**, nunca todo-o-nada; no se suma a un rollo revelado.
- `left_at` (salirse) y `removed_at` (lo sacó el admin) son marcas distintas. El admin **no puede salirse**.
- Mensajes de error al usuario en español rioplatense (voseo); código, identificadores, comentarios y tests en inglés; commits y PRs en español, con `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`.
- TDD (test primero, verlo fallar). Migraciones nuevas, nunca se edita una ya aplicada. No se renombra nada persistido en el celular.

## Review Focus

- Código de amistad con minúsculas, espacios o guiones al canjear → se normaliza como el de login. (B2)
- Canjear con código vencido, ya reemplazado por uno nuevo o inexistente → mismo error genérico, sin revelar cuál. (B2)
- Muchos intentos fallidos por usuario o por IP → bloqueo con 429. (B2)
- Sumar a un amigo que ya es miembro, que se salió, que sacó el admin, o que ya no es amigo → resultado por amigo, sin fallar el pedido entero. (B3)
- Un usuario que abre su propio link, o el de alguien que ya es su amigo → no pasa nada, sin error. (B2)
- Borrar una cuenta con amigos y links vivos → se limpian; el amigo sigue viendo sus rollos. (B4)
- App: link abierto con sesión vencida o sin perfil completo, y un segundo link mientras hay uno pendiente. (A3)

### Task B2: Endpoints de amistad

**Files:**
- Create: `src/routes/friends.ts`, `test/friends.test.ts`
- Modify: `src/index.ts` (montar `friends` en `/friends` y `friendLinks` en `/friend-links`), `src/schemas.ts` (schemas `FriendSchema`, `FriendLinkSchema`, `ClaimResponseSchema`), `test/helpers.ts` si hace falta un helper `befriend(tokenA, tokenB)`.

**Interfaces:**
- Consumes: B1 (`generateFriendCode`, `normalizeFriendCode`, `pairKey`, TTLs), `requireUser`, `hashToken`.
- Produces (contrato que usa la app):
  - `POST /friends/link` (sesión) → 200 `{ code: string, expiresAt: number }`; invalida los links anteriores del usuario.
  - `POST /friend-links/claim` (**sin sesión**) body `{ code }` → 200 `{ claimToken: string, expiresAt: number, creator: { name: string, username: string | null, avatarUrl: string | null } }`; 400 `"Código incorrecto o vencido"` en cualquier falla.
  - `POST /friends/redeem` (sesión) body `{ code?: string, claimToken?: string }` (exactamente uno) → 200 `{ friend: Friend }`; 400 mismo mensaje genérico; 429 `"Demasiados intentos, probá más tarde"`.
  - `GET /friends` (sesión) → 200 `{ friends: Friend[] }` ordenado por nombre, con `Friend = { id, name, username, avatarUrl }`.
  - `DELETE /friends/{userId}` (sesión) → 204 (también si no eran amigos).

### Task B3: Sumar amigos, salirse y reglas de pertenencia

**Files:**

**Interfaces:**
- Consumes: B2 (`friendships`), `requireTripMember`.
- Produces:
  - `POST /trips/{tripId}/members` (sesión, miembro del rollo) body `{ friendIds: string[] }` (1 a 50) → 200 `{ results: { userId: string, status: "added" | "already_member" | "unavailable" }[] }`. `unavailable` cubre: no es tu amigo, lo sacó el admin, o el rollo ya se reveló (en ese caso 409 `"Este rollo ya se reveló"` para todo el pedido). Quien se salió y vuelve: se reactiva la fila (`left_at = NULL`) y cuenta como `added`. Guarda `added_by_user_id`.
  - `DELETE /trips/{tripId}/members/me` (sesión) → 204 y `left_at = now`; 409 `"Sos el admin: no podés salirte del rollo"` si es admin.
  - `join` por código: si la fila tiene `left_at`, se reactiva; si tiene `removed_at`, sigue siendo 403.
